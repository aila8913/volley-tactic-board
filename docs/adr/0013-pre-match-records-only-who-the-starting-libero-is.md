# ADR-0013：賽前只記「誰是先發自由球員」，不記「他頂替誰」

狀態：Accepted（2026-08-15）

## 背景

自由球員的表示法被改過兩次。**#326**（08-10）把 `liberoZones`（L 在六輪各站哪一格）換成
`liberoReplacesPlayerId`（L 頂替誰）——舊形狀一次換人要記六次，漂掉一份就是 #14 那串「畫面上
兩個 L」。同一張票刪掉「接替啟發式」，判準是**這個 app 產出的是紀錄，不是示意圖**：猜出來的
替換會在紀錄裡產生一次根本沒發生過的事。**#327**（同日）加了輪轉表第七格，但它一次承接了
兩個決定：誰是先發 L、以及他頂替誰。

**#425**（08-15）推翻後者。PO：「L 不用先指定要頂替誰，只要表示誰是 L 的先發球員而已。」
排球規則上先發六人本來就不含自由球員。

## 決定

**賽前只記 `startingLiberoId`。「頂替誰」是賽中的事實，只由球場上那顆 L 鈕寫進
`useScoreSheet` 的 `record.liberoSubstitution`。**（PR #426：store 欄位移除，
`setLiberoAssignment` 收斂成 `setStartingLibero`。）

這不牴觸 #326，是同一條判準的延伸：賽前那一刻一次替換都還沒發生，寫下的「L 頂替 12 號」是
**計畫**，卻會被凍進該局的先發快照、讀起來像**紀錄**。被推翻的是 #327 的一半，不是 #326。

**DB 與 OpenAPI 不動。** `lineups` 的註解本來就列了三種合法狀態，本決定要的就是其中的
(b)「只有 `startingLiberoId`、開局 L 在場外」——schema 早就允許，只是從例外變成常態。
完整對照表在 #425。

## 後果

- 少一欄 ＝ 少一種「兩邊對不起來」的可能，連帶刪掉 `setRoster`／`setLineupZones` 裡兩段
  「頂替對象要不要失效」的清理規則。
- **把 L 拖到六個號位不再有任何效果**——那六格是先發六人的輪轉序，L 不佔輪轉序。
- 開賽凍結時 `replacesPlayerId` 一律寫 `null`；`deriveRotation` 純函式沒改，只是輪轉表那一側
  改為恆餵 `null`（計分頁球場仍餵賽中的 `liberoSubstitution`）。
- 唯讀路徑保留：看**已封存的那一局**時快照裡可能真的有值，畫得出來才不會漏講那一局的事實。

## 不要重新提議

- **改回 `liberoZones`**——#326 已否決，一次換人記六次必然漂走。
- **賽前讓教練先指定頂替對象**——本張否決的就是這個。理由不是「使用者懶得填」，是**那個值
  會被當成紀錄讀**。
- **把 DB 那兩欄 drop 掉**——狀態 (c) 是真事實（L 常在第一球之前就換上場），刪掉等於宣告
  「開局 L 永遠不在場上」。附帶成本見 #425。
- **「欄位恆為 null，一定是漏接了寫入路徑」**——最可能的復發形狀，因為 DB 欄位與
  `deriveRotation` 的參數都還在，看起來就像少接一條線。**那條線是刻意不接的**，它的來源在
  賽中不在賽前。
