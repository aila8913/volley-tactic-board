# ADR-0012：戰術板中央只畫白板，沒在編就是空的

狀態：Accepted（2026-08-15）

## 背景

戰術板中央的 `Court.tsx` 長期一支元件兼兩種畫法，由 `useTacticsBoard.courtView` 切換：
「輪轉」畫輪轉表的先發（球員吸附六個號位、旁邊一顆 L 備位圓圈、不能畫筆），「戰術」畫
一份可編輯／唯讀的戰術快照。

那顆開關**沒有任何按鈕能切**——它只是 `startSession` / `discardSession` / 切輪次的副作用，
畫面上也沒有任何地方說明現在是哪一種。PO 2026-08-07 實測的回報是「看不懂輪轉視圖是什麼、
也從來沒看到過它」。查證後這個反應是對的：六格拖曳與輪次切換在 #174／#251 已搬進右欄的
`RotationRailPanel`，最後一件獨有的職責（指定先發自由球員）在 #327 交給了輪轉表第七格。
它不是被設計出來的畫面，是被剩下來的。

## 決定

**中央球場只畫白板：有 session 畫可編輯的快照，有 viewingScene 畫唯讀的已存戰術，
兩者皆無就是一塊空球場。**`courtView` 整個拿掉（#328）。

連帶：戰術板僅存的兩支「寫回輪轉表」動作（拖球員上場 `placePlayerOnCourt`、拖進備位框
`setStartingLiberoId`）隨那半邊畫法一起刪除。**這不是新決定，是 ADR-0001 終於在 UI 上
落實**——那張 ADR 的後果段早就寫著「戰術頁的輪轉表變成純對照用參考物、不能編輯」。

## 後果

- 「排先發」現在只有計分頁一個入口，「指定先發自由球員」只有右欄第七格一個入口。每件事
  一個入口，不再有兩個長得不一樣、行為也不一樣的地方做同一件事。
- mode B（沒在編）的中央是一塊空球場。右欄名單因此關掉 `benchDraggable`——沒有 session
  就沒有東西接得住拖曳，可拖但拖了沒反應比不能拖更糟。
- 「重置站位」改名「重置先發」：它清的是右欄那份先發，中央不再畫先發之後，名字必須指出
  它作用在哪一份資料（#324 的「按了沒反應」正是名字沒說清楚造成的）。

## 不要重新提議

- **「中央空著很奇怪，把輪轉站位畫上去當唯讀參照」**——這正是被退役的那個畫面。想看站位
  右欄一直都看得到，而且是同一份資料的唯一一份呈現；中央再畫一份就會出現「兩邊對不起來」
  （右欄第七格用起始站位算場外，中央會跟著 stepper 轉），那組矛盾就是這張要收掉的東西。
- 「把 L 備位圓圈加回球場邊」——`#326` 之後自由球員的模型是「L 頂替誰」，不是「L 站哪個
  座標」，球場上沒有位置能誠實表達它。
- 「補一顆按鈕讓使用者自己切換兩種畫法」——已評估：問題不是「開關藏起來了」，是那半邊畫面
  已經沒有獨有職責。給一個沒有內容的畫面加入口，只是把遺留物變成正式功能。
