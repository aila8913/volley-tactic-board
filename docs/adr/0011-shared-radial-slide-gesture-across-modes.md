# ADR-0011：兩個模式共用同一套滑選手勢（部分取代 ADR-0010）

狀態：Accepted（2026-08-13，PO 實機試玩 #392 之後定案，執行票 #410）

部分取代 **[ADR-0010](0010-advanced-recording-gesture-and-trajectory-model.md)**「後果」段落的
「刻意不改簡易版」那一條。ADR-0010 的其餘決定（滑＋tap 兩下手勢、折線座標、就地升級、動作手動選、
影片獨立成表）**全部仍然成立**。

## 背景

ADR-0010 拍板進階版補填採「按住球員 → 滑向動作 → 放開」的環形滑選，並且注意到一件事：簡易版
（賽中即時記錄）的球場手勢方向**相反**——那邊是從球員畫線出去、鬆開時命中目標。同一個球場上
兩種相反方向的拖曳，肌肉記憶會打架。

當時的解法是**讓兩套並存**，靠模式明確（膠囊切換）＋ 翻轉動畫去彌補，理由是「簡易版是已經在用的
東西」。

2026-08-13 PO 實機把 #392 走過一遍之後推翻了這個解法。

## 決定

**兩個模式用同一套滑選手勢，簡易版跟著改（#410）。**

推翻的不是 ADR-0010 的觀察，是它的結論。原本的推理是對的——「兩個相反方向」確實會打架——但它
選錯了要動的那一邊：真正的問題是**存在兩個方向**這件事本身，而不是「哪一邊該讓步」。用「已經在
用的東西不要動」當理由，等於讓先落地的那個版本自動獲得否決權，而它先落地跟它比較好用之間沒有
任何關係。PO 兩邊都實際用過之後的判斷是滑選比畫線好用，所以該讓步的是舊的那一邊。

判定與畫面的共用機制在 #392 就已經備好了，不是為了這張 ADR 另外設計的：
`lib/courtGesture.ts`（`radialSelection` / `radialOptionOffsets` / 死區常數）＋ `RadialMenu`，
兩個模式吃同一份角度數學，畫出來的選項位置跟命中判定不會漂走。

## 後果

- 簡易版的 `gesture` 狀態機（`ScoreSheet.tsx`）與 `ScoreSheetCourt.tsx` 的畫線手勢要改寫 → #410。
  在那張票落地之前，兩套手勢仍然並存，這是過渡狀態，不是新的穩定態。
- `AdvancedRecordingCourt.tsx` 檔頭「為什麼不共用 ScoreSheetCourt」的第 2 點引用了 ADR-0010 那條
  「刻意不改簡易版」——**該理由的另一半仍然有效**：分成兩個檔案是為了讓 #392 的 diff 肉眼可證
  「簡易版一行沒動」。手勢統一之後，兩個元件要不要合併是另一個問題，不由這張 ADR 決定。
- 選項本身（6 動作 ＋ 取消該怎麼分類）是獨立的問題，追在 #411，不在這張的範圍。

## 不要重新提議

- **別再用「簡易版是已經在用的東西」當作不改它的理由。** 這正是 2026-08-13 被推翻的那條推理。
  先落地不代表比較好用；要保留舊手勢請提出「它在哪個情境下真的比較好」的理由。
- **別把兩套手勢的選單各寫一份選項座標／命中判定。** 兩邊共用 `lib/courtGesture.ts` 是刻意的：
  這 repo 已經在 #352 踩過「同一段算式兩份手寫拷貝、改一邊忘了改另一邊」的坑。
- **別把「取消」畫回動作環的圓心。** 動作環的圓心是**球員本人**，在他頭上壓一個 ✕ 會讀成
  「刪掉這個球員」而不是「不選動作」——所以取消佔環上的第 7 格（PO 2026-08-13 當場的指正）。
  得失分環例外，它的圓心是球場上一個空點，✕ 留在那裡沒有歧義。
- **別把收尾這一分的「停駐 1 秒」合併回全站那個 500ms 的長按常數**（`DWELL_MS` vs
  `LONG_PRESS_MS`）。它疊在「點落點」這個動作上面——同一根手指、同一次按壓，短放是記落點、
  久按是收尾——所以等待時間必須明顯長過「使用者只是在找落點順手停一下」。理由與實作寫在
  `lib/courtGesture.ts` 那兩個常數的註解。
